# Hi3516CV610 encoder backend

`MABUR_VENC_BACKEND=cv610` replaces the SigmaStar encoder behind
`drone/venc/venc_core.h` with one for the Hi3516CV610. `star6e` stays the
default; the two share no source except the frame ring, the IDR limiter and
the config helpers.

| File | Role |
|---|---|
| `drone/venc/cv610_pipeline.{h,c}` | MIPI, VI, ISP, 3A, VPSS; the sensor table |
| `drone/venc/venc_core_cv610.c` | the VENC channel, encoder thread, facade verbs |
| `cmake/arm-cv610.cmake`, `tools/build-cv610.sh` | the cross-build |

## Build

```sh
CV610_TOOLCHAIN_BIN=<toolchain>/bin \
MABUR_CV610_SDK_INC=<openhisilicon checkout> \
MABUR_CV610_SDK_LIB=<dir with libss_mpi.so and friends> \
tools/build-cv610.sh     # out/cv610/maburd
```

The toolchain has to be `arm-openipc-linux-musleabi`: the MPP libraries are
soft-float musl shared objects and the sensor plugin is opened with `dlopen`,
so a hard-float or a static binary cannot load them. The headers come from
OpenHisilicon and the libraries from the HiSilicon SDK; neither is in this
repository.

## Running

The image has to provide the MPP kernel modules, loaded by its own init before
maburd starts, and the sensor plugin `/usr/lib/sensors/libsns_imx335.so`.
OpenIPC images link the MPP into Majestic and carry no MPP shared libraries,
so the `.so` files listed in `drone/CMakeLists.txt` have to reach the camera and
`LD_LIBRARY_PATH` has to name them. Majestic owns the same hardware: stop it
first with its init script. Do not unload the MPP modules, which hangs the SoC
under a live consumer.

`venc.sensor_bin` is still required by the config loader and is ignored: the
plugin carries the ISP tuning.

## Modes

The sensor runs one mode, IMX335 2592x1944 at 30 fps, 4 lanes, RAW12, on i2c-0.
`venc.fps` above 30 fails boot; below 30 the encoder drops frames. `venc.size`
can be any size that fits in the mode: VPSS centre-crops the capture to the
output's aspect and scales. `venc.binning` has no effect.

## Verbs

| Verb | State |
|---|---|
| `venc_core_start`, `_stop`, `venc_get_stats`, `venc_cur_pts_us` | implemented |
| `venc_core_restart` | rebuilds the VENC channel and the VPSS output; the sensor, VI and ISP keep running |
| `venc_set_bitrate_kbps`, `venc_request_idr` | implemented |
| `venc_set_fps` | destination rate up to 30, with the GOP re-derived to keep its length in seconds |
| `venc_set_roi_qp` | accepted and ignored, warns once: a refusal would make RcAgent re-send every verb on each tick |
| `venc_set_qp_delta`, `venc_set_max_ipprop`, `venc_set_superframe_p_pct`, `venc_set_min_iqp`, `venc_set_max_iqp`, `venc_set_sensor_offset`, `venc_snapshot_jpeg`, `venc_record_start` | return -1 |

`venc.intra_refresh_frames`, `venc.slices` above 1 and `venc.roi.enabled` log a
warning at start and are ignored. `venc_set_sensor_offset` returning -1 means
the phase lock (`docs/phase-lock.md`) cannot steer this sensor.
